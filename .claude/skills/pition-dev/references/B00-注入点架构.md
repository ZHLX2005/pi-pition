# B 序列：注入点架构

`pition` 通过 pi 的 `ExtensionAPI`（`@earendil-works/pi-coding-agent/dist/core/extensions/types.ts`）在 5 个维度向宿主进程注入行为。本序列定位 **「pition 在哪些点修改了 pi 行为」**，用来回答两类问题：

1. **新增能力时**：「我想加 X 行为，应该走哪个注入点？」（→ B01）
2. **排查 bug 时**：「我看到的 Y 行为是 pition 注入的，还是 pi 自己的？」（→ B01）

## 序列内路由

| 成员 | 何时读取 | 内容 |
| --- | --- | --- |
| **B01** | 想知道 pition **当前**的所有注入点 | 5 维度的清单 + 位置 + 行号 + 契约 |
| （未来 B02+） | 想新增「注入点模板」（如：tool 模板、event handler 模板） | 各模板的最小可运行代码片段 |

## 注入点 5 维度（顶层分类）

| 类型 | API | 作用 | 在 pition 里的位置 |
| --- | --- | --- | --- |
| **Tool** | `pi.registerTool()` | 让 LLM 可调用的工具 | 5 个（boot / stores / query / add_entry / update_latest） |
| **Command** | `pi.registerCommand()` | 用户的 `/xxx` 斜杠命令 | 2 个（`/pition`、`/pition-mode`） |
| **Event** | `pi.on(event, handler)` | 订阅生命周期事件并改写上下文 | 2 个（`before_agent_start`、`session_start`） |
| **设置落盘** | `pition.config.json` | 持久化配置（pi 不读，pition 启动时一次性读） | `_assistantMode` 字段 |
| **CLI Flag / Shortcut** | `pi.registerFlag/Shortcut` | 当前未用 | — |

> **Context Prompt 注入** 不是独立的 API，是 `before_agent_start` 事件的 `event.systemPromptOptions`（`promptGuidelines` + `sections`）——所以归在 Event 维度。

## 5 维度选择决策树

```
我想要做的事
├─ 让 LLM 在对话里主动调用 → Tool
├─ 用户在 TUI 里手动触发 → Command
├─ 改 pi 给 LLM 看的提示词（指南 / 自定义区段 / 模型选择 / 工具集） → Event: before_agent_start
├─ 在会话开始 / reload 时刷新自身内存 → Event: session_start
├─ 重启后还生效的配置 → 写 pition.config.json（设置落盘维度）
├─ CLI 参数 / 快捷键 → Shortcut / Flag
└─ 其它（自定义 UI 组件 / Provider / MessageRenderer）→ 见 pi 文档，B01 不展开
```

## 与其它序列的关系

- **A 序列**：A01 是「引导态设计」（`pition_boot` 的 5 阶段契约）。B 序列不重复——B01 只索引 `pition_boot` 的注入位置（Tool 里），不展开其契约。
- **未来 C 序列**（如果有）：扩展「测试 / 验证注入点」模板时使用。

- 想理解配置字段语义 → SKILL.md「配置格式」+ A01
- 排查扩展不加载 / 工具不出现 → SKILL.md「排查阶梯」
