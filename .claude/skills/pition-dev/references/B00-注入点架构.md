# B 序列：注入点架构

`pition` 通过 pi 的 `ExtensionAPI`（`@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts`）
在 6 个维度向宿主进程注入行为。本序列定位 **「pition 在哪些点修改了 pi 行为」**，回答两类问题：

1. **新增能力时**：「我想加 X 行为，应该走哪个注入点？」（→ B01）
2. **排查 bug 时**：「我看到的 Y 行为是 pition 注入的，还是 pi 自己的？」（→ B01）

## 序列内路由

| 成员 | 何时读取 | 内容 |
| --- | --- | --- |
| **B01** | 想知道 pition **当前**的所有注入点 | 6 维度清单 + 位置 + 契约 + 运行态陷阱 |
| （未来 B02+） | 想新增「注入点模板」（tool 模板 / event handler 模板） | 各模板的最小可运行代码片段 |

## 注入点 6 维度（顶层分类）

| 类型 | API | 作用 | 在 pition 里的位置 |
| --- | --- | --- | --- |
| **Tool** | `pi.registerTool()` | 让 LLM 可调用的工具 | 7 个（boot / write / read / history / create_today / span / goal）——**全部无条件注册** |
| **Command** | `pi.registerCommand()` | 用户的 `/xxx` 斜杠命令 | 2 个（`/pition`、`/pition-mode`） |
| **Event** | `pi.on(event, handler)` | 订阅生命周期事件并改写上下文 | 4 个订阅（`before_agent_start`、`session_start` ×2、`tool_execution_end`） |
| **上下文注入** | `before_agent_start` 的 `event.systemPromptOptions` | 改 `promptGuidelines` / `toolGuidelines` / `sections` / `selectedTools` | 6 个 section + tool 足迹裁剪 → [[C01-上下文多层结构]] |
| **设置落盘** | `pition.config.json` | 持久化配置（pi 不读；每次 execute 经 loadConfig 重读） | `_assistantMode` / `_activeSpans` / `_activeGoals` |
| **CLI Flag / Shortcut** | `pi.registerFlag/Shortcut` | 当前未用 | — |

> **上下文注入**归属 Event 维度（不是独立 API），但它的体量已经值得单列——它决定「模型看到什么」，
> 有独立的**分层设计 + 场景路由 + 状态驱动片段 + 易变层隔离 + 预算门禁**。
>
> 其中**与 pition 领域无关的机械**已抽到 `src/injection/`（整目录可复制到别的扩展复用，
> 见 `src/injection/README.md`）；B01 里讲到的注入位置不变，只是实现搬了家。

## 6 维度选择决策树

```
我想要做的事
├─ 让 LLM 在对话里主动调用 → Tool（记得补 promptSnippet + 场景片段）
├─ 用户在 TUI 里手动触发 → Command
├─ 改 pi 给 LLM 看的提示词（准则 / 自定义区段 / 工具足迹 / 模型 / 工具集） → Event: before_agent_start
│    └─ 具体往哪层注入？→ C01 §3 决策树（恒定 core / 场景片段 / 易变 runtime）
├─ 在会话开始 / reload 时刷新自身内存 / 清会话级状态 → Event: session_start
├─ 让上一轮工具的结果影响下一轮提示词 → Event: tool_execution_end（→ SessionFacts → 易变层）
├─ 重启后还生效的配置 → 写 pition.config.json（设置落盘维度）
├─ CLI 参数 / 快捷键 → Shortcut / Flag
└─ 其它（自定义 UI 组件 / Provider / MessageRenderer）→ 见 pi 文档，B01 不展开
```

## 与其它序列的关系

- **A 序列**：A01 是「引导态设计」（`pition_boot` 的 5 阶段契约）。B 序列不重复——B01 只索引它的注入位置。
- **C 序列**：「模型看到什么」的架构。B01 §3 列**注入位置**，C01 讲**内容怎么分层 + 场景怎么路由 + 预算怎么算**。

## 何时**不**读本序列

- 想理解 tool 的执行细节（调用契约）→ 读 SKILL.md 的「Tool 一览」+ `src/tools/`
- 想理解配置字段语义 → SKILL.md「配置格式」+ [[A01-设计理念]]
- 排查扩展不加载 / 工具不出现 → SKILL.md「排查阶梯」
