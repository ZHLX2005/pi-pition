# B01 注入点清单

## 1. Tool 注入点（7 个）

| # | tool 名 | 定义位置 | 何时调用 | 是否可扩展 |
| --- | --- | --- | --- | --- |
| 1 | `pition_boot` | `src/tools/boot.ts#defineBootTool` | 引导态：5 阶段配置（token → select_db → describe_fields → set_mode → done）；切空间也走 boot | 加 stage：`Type.Union` 加 Literal + `boot-run.ts` 加分支；契约校验见 `scripts/smoke-load.mjs` |
| 2 | `pition_write` | `src/tools/write.ts#defineWriteTool` | **日常主路径**：改当前 page 属性（默认 append 合并）+ 追加正文；返回 todaySoFar 预览 | 加新参数 |
| 3 | `pition_read` | `src/tools/read.ts#defineReadTool` | 读当前 page 完整内容 | 加新参数 |
| 4 | `pition_create_today` | `src/tools/create_today.ts#defineCreateTodayTool` | **逃生口**：仅当 write 返回 warning「没有 page」时用 | 加新参数 |
| 5 | `pition_history` | `src/tools/history.ts#defineHistoryTool` | 翻旧账时显式查 page 列表（不是默认背景） | 加 filter 算子 |
| 6 | `pition_span` | `src/tools/span.ts#defineSpanTool` | **区间事件**：start 落 cfg、end 写整段进 page；end 可联动 goal | 加 action / 联动参数 |
| 7 | `pition_goal` | `src/tools/goal.ts#defineGoalTool` | **每日目标**：set/progress/list/update/delete；进度注入；autoPeriod；bindField | 加 action / period 类型 |

**契约**：

- 注册参数一律 `Type.Array(Type.Object({name, value}))`（属性条目），禁 `Type.Record`——后者对 MiniMax 参数解析坏（字段名变 `$text`）
- **`promptSnippet` 必填**（一行，进 tools 层 Available tools 索引）；`promptGuidelines` ≤3 条工具自身机理
- **description 不写 cfg 衍生字符串**（库标题 / 字段说明 / 助理模式状态）——要字段名指向注入的 `pition_fields` 段。唯一例外是 `pition_boot`（见 §0）
- 每个 tool `execute` 第一行调 `currentBinding()` / `loadConfig()` 重读（§6.1）；返回走 `detail({...})`

## 2. Command 注入点（2 个）

| # | 命令 | 位置 | 行为 | 是否可扩展 |
| --- | --- | --- | --- | --- |
| 1 | `/pition` | `src/wizard.ts#registerSetupCommand` | 4 步 TUI 向导（token → 选库 → 看结构 → 补说明）；RPC 走 `extension_ui_request` | 在 `wizard.ts` 加步骤；中途取消不落盘 |
| 2 | `/pition-mode` | `src/role-mode.ts#registerRoleMode` | toggle `_assistantMode`；落盘 + 同步运行态 `roleState.enabled` / 清空 `lastScene` | 描述改文案即可；等价入口 `pition_boot stage=set_mode` |

**契约**：命令必须**无条件注册**（`registerSetupCommand(pi)` 在 `loadConfig()` 之前调用），否则未配置时进不去向导，形成死锁。

## 3. Event 注入点（4 个订阅 + 注入面 6 个）

| # | 事件 | 位置 | 行为 | 是否可扩展 |
| --- | --- | --- | --- | --- |
| 1 | `before_agent_start` | `src/injection/runtime.ts#createInjectionRuntime`（`registerRoleMode` 里 `attach`） | 场景路由 + 状态快照 + 分层注入 + tool 足迹裁剪 + 运行时事实注入（详见 §3.1） | 加注入维度：加/改 section 内容，**不要**加新 section 名，更不要 `forceSystemPrompt` |
| 2 | `session_start` | 同上（内核 `resetRuntimeState`；另有 `extensions/pition.ts` 里的一个负责重读 cfg） | 会话事实清零（新会话不继承「已写入 N 条」）+ 清场景粘性 | 任何会话级运行态变量都在这里清 |
| 3 | `tool_execution_end` | 同上（内核采集 → `applyOutcome`） | 采集 pition tool 的结果（成功/警告/失败）进 `SessionFacts`，供下一轮易变层与片段选择用 | 只观察不改写；新 tool 的 warning 走 `details.warning` 自动被采集 |
| 4 | `session_shutdown` | 未用 | （如需释放资源用） | — |

**契约**：

- 用 `promptGuidelines.push(...)` / `sections[name] = content` / `toolGuidelines[name] = []` 增量注入 —— **保留 pi 默认 prompt prefix**，cache 命中
- 同一个事件可以有多个 handler（pi 按注册顺序跑全部）——`session_start` 就注册了两个（各自职责单一）
- `tool_execution_end` 的 payload 是 `{ toolCallId, toolName, result, isError }`；`result` 形状容错处理（见 `prompt-state.ts#outcomeFromEvent`）

## 4. 设置落盘点（`pition.config.json`）

| # | 字段 | 写入位置 | 作用 |
| --- | --- | --- | --- |
| 1 | `token` | `boot-run.ts`（stage=token）、`wizard.ts`、`scripts/install.mjs` | Notion API bearer |
| 2 | `bindings`（按 dbId 索引） | boot stage=select_db / describe_fields、wizard | 库绑定 + 字段说明（切空间保留所有 desc） |
| 3 | `currentBindingId` | boot stage=select_db / describe_fields、`normalizeConfig` 老格式归一 | 当前激活库；运行时由 `currentBinding()` 重读 |
| 4 | `_assistantMode` | boot stage=set_mode、`/pition-mode` | 助理模式开关（缺省 false） |
| 5 | `_activeSpans` | `pition_span action=start/end` | 进行中的区间事件（数组，可并行） |
| 6 | `_activeGoals` | `pition_goal` set/progress/update/delete + 跨天物化 | 按天持久的目标（按 date 分区，无清理） |

**契约**：

- pi 进程不读这个文件 —— 它是 pition 自己的存储格式
- 路径：npm 安装形态落 `<agent-dir>/extensions/pition.config.json`（重装不丢）；仓库开发形态 walk-up 找包内配置；`PITION_CONFIG` 可显式覆盖（测试/容器）
- 写入一律「读 → 展开保留全部字段 → 写回」，**不要重建字面量**（会丢 `_activeSpans` / `_activeGoals`）
- 兼容老格式：`bindings: [...]` 数组 → `{ [dbId]: b }`；`_activeSpan` 单对象 → `_activeSpans` 数组

## 6. 运行态陷阱（必读）

> **加任何新 tool / 改 tool 描述 / 改注入面前必看本节。**

### 6.1 启动时闭包 cfg → 切库后所有 tool 仍查旧库

**症状**：切库后 `pition_history` 返回的还是旧库的 page。

**根因**：`const primary = cfg.bindings[cfg.currentBindingId]` 在工厂执行时求值一次就锁定了。

**修复契约**：`currentBinding()` / `currentSpans()` / `currentGoals()` 放在工厂外，每次调用重新 `loadConfig()`；
每个 `execute` 第一行调用它；所有 Notion 调用走 `notion(cfg ?? loadConfig(), ...)`。

### 6.2 description 静态拼接 storeCtx → 切库后 agent 看到的字段说明还是旧库

**修复契约**：description 里**不**写库标题、**不**拼字段说明、**不**写死任何 cfg 衍生字符串；
字段名统一指向每轮注入的 `pition_fields` 段（v0.5.0 起该段真的会注入）。

> `pition_boot` 的 description **可以**动态拼 `bootCtx`——它本身就是查 cfg 的工具，每次调用都重读，
> 拼装一次没风险（不像运行态 tool 的 description 是注册期静态的）。

### 6.3 keep-alive socket 卡死 → `fetch failed`

**修复契约**（`src/notion.ts#fetchNotion`）：`Connection: close` + 5s `AbortController` 超时 +
指数退避 3 次（仅网络层错误）+ 网络错误白名单（`fetch failed` / `ECONNRESET` / `ETIMEDOUT` / …）。

### 6.4 【最严重】工厂期用 cfg 做注册门禁 → 会话中现配的库永远看不到运行态 tool

**症状**（2026-09-29 实证）：用户在会话里一步步配完 Notion，配完后 `pition_span` / `pition_write` /
`pition_read` 全都不在工具列表里，只有 `pition_boot` 可用，必须 `/reload`。

**根因**：`pi.registerTool` **只在工厂执行期有效**——`if (!snapshotCfg.currentBindingId) return;` 之后
无法补注册；而「首次使用」的配置动作恰恰发生在会话中，门禁必然误伤。

**修复契约**：**运行态 tool 全部无条件注册**，校验下沉到 `execute` 首行 `currentBinding()`
（抛错指引 agent 去 `pition_boot`——比"工具根本不存在"好得多）。

> **推论**：任何「配置齐了才有意义」的能力，都不要用注册期门禁；一律注册 + 运行时判。

### 6.5 【v0.5.0】别把 `setActiveTools` 当场景门禁

`setActiveTools` 能按场景摘掉不需要的 tool——**不要用**。摘掉 = 模型调不到，用户此刻真要记东西时
只能干看着（与 §6.4 同一类问题的另一副面孔）。正确做法：工具集恒为 7 个，只裁 **guideline 文本**
（`role.ts#pruneToolGuidelines`），tool 的 description 仍在 schema 里随时可查。

### 6.6 【v0.5.0】别把 SOP 写成固定长文

同一场景下的**固定长文**必然塞进当下不成立的内容——典型：用户的目标已经建好，剧本还在教
「先了解身体情况再 set」。这是噪音，还会误导模型（用户反馈「提示词很容易变得静态」的根因）。
正确做法：拆成 `SopFragment`（`when(state)` + `text`，文案可为函数以插入真实数字），
状态只从 `PromptState` 取。改完跑 `test/sop.test.ts`（它会断言片段集随状态变）。

### 6.7 【v0.5.0】改注入面必须刷新预算台账

改了 tool 描述 / `promptSnippet` / `promptGuidelines` / `src/sop.ts` 片段 / `src/prompt-state.ts` /
skill frontmatter / `role.ts` 的恒定段，都要 `npm run context:generate` 刷新 `docs/context-budget.json`，
否则 `npm run check` 会红。超上限时**不要直接抬上限**——先把细节挪回 `skills/*.md`（on-demand），
抬上限要有明确理由。

### 6.8 【v0.5.0】注入前必须探测宿主能力（否则静默零注入）

`sections` / `toolGuidelines` 是 **pi 0.86 才有的**（0.85 实测没有）。旧宿主上 `sections[x] = y` 会抛
TypeError → 被 pi 的错误边界吃掉 → **每轮零注入且不报错**（表现为「模型不听话」，极难查）。

契约：`src/injection/host.ts#supportsStructuredInjection(opts)` 为假时**整体跳过**结构化注入 +
`ctx.ui.notify` 提示一次（每会话一次）；装配/渲染抛错时降级为最小 `pition_core`。
**不要**凭空创建宿主没声明的字段。探测/跳过/降级/**先构造后落地**都由
`src/injection/runtime.ts#createInjectionRuntime` 统一编排——不要在 `role-mode.ts` 里另写一份。

### 6.9 【v0.5.0】改了注入面要过真宿主校验

`test/host-injection.test.ts` 用真实 loader + `ExtensionRunner` 跑 `before_agent_start`：
写入是否被采纳、裁剪是否经真实合并生效、同状态两轮 options 是否深度相同（＝ 不刷 cache）。
只测 `test/extension.test.ts` 的「假 pi」验证不了这些——那是测我们自己写的假设。
排障：`node scripts/dev/diag-injection.mjs "<用户原话>"`。

### 6.10 【v0.6.0】机械在 `src/injection/`，别在领域模块里重实现

与 pition 领域无关的注入机械已抽到 `src/injection/`（整目录可复制到别的扩展复用）：
`version/host/clock/facts/router/fragments/layers/prune/bytes/runtime`。
`role-mode.ts` 现在只填四个领域插槽（`buildState` / `build` / `runtimeSections` / `fallback`）。

| 别这么做 | 该这么做 |
| --- | --- |
| 在 `role-mode.ts` 里自己写「探测 → 构造 → 落地 → 降级」 | 交给 `createInjectionRuntime`（顺序踩过坑，重拼必错一处） |
| 在 `sop.ts` 里自己写片段谓词求值 | 用 `src/injection/fragments.ts` 的 `renderSceneBody` / `activeFragmentIds` |
| 在 `scene.ts` 里自己写优先级遍历 + 粘性 | 用 `src/injection/router.ts` 的 `createRouter` |
| 往 `src/injection/` 里 import 领域模块 | 内核必须零外部依赖（`test/injection.test.ts` 有守卫断言） |

排障时先分清「这段是机械还是领域」：机械问题去 `src/injection/README.md`，
领域问题才回 `role.ts` / `sop.ts`。

**v0.7.0 起有脚手架**：`node scripts/new-extension.mjs <目录> --name <名字>` 一条命令把内核
逐字节复制过去并生成可跑的骨架（pi 下界从 `src/injection/version.ts` 读，不会抄错成旧版本）。
自检在 `test/new-extension.test.ts`。

## 完整注入点拓扑图

```
extensions/pition.ts（纯装配层）
├── registerSetupCommand(pi)            ← /pition 命令（无条件）
├── registerRoleMode(pi, roleState)     ← 助理模式
│   ├── pi.on("before_agent_start")     ← Event #1：场景路由 + 状态快照 + 6 个注入面
│   ├── pi.on("session_start")          ← Event #2：会话事实清零 + 场景粘性清零
│   ├── pi.on("tool_execution_end")     ← Event #3：pition tool 结果回流
│   └── pi.registerCommand("pition-mode") ← /pition-mode 命令
├── pi.on("session_start")              ← Event #2'：重读配置（reload 后 roleState.cfg）
└── 7 个 tool 全部【无条件】注册（无工厂期门禁 —— §6.4）：
    ├── pition_boot（引导态元工具）
    └── 运行态 tool（execute 首行 currentBinding() 重读 cfg）：
        pition_write / pition_read / pition_span / pition_goal / pition_history / pition_create_today
```

## 维护提示

- 改注入点前先查本清单是否覆盖；改完更新**位置与函数名**（不要写行号——代码按职责拆分）
- 字段契约 / 调用示例属契约层 → 放 SKILL.md 的「Tool 一览」与 `pition_boot` 段；本清单只列**注入点 + 运行态陷阱**
- 新增注入点维度（renderer / 自定义 UI 等）时，**先扩展本文件的表格**，再写代码
