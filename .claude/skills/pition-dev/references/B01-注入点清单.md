**契约**：
- 所有 tool 注册参数都用 `Type.Array(Type.Object({name, value}))`（属性条目）而非 `Type.Record`——后者对 MiniMax 模型参数解析坏（字段名变 `$text`）。改 schema 时保留这个模式。
- **description 不写 cfg 衍生字符串**（库标题 / 字段说明 / 助理模式状态等），统一指引 agent 调 `pition_boot stage=done` 拿当前 schema（运行时解析，永远最新）。详见 §6.2。
- **每个 tool execute 第一行调 `currentBinding()`**（factory 栈外的 helper，`extensions/pition.ts:678`），从 cfg 重读当前 binding id；不依赖启动时闭包。详见 §6.1。

## 4. 设置落盘点（`pition.config.json`）

| # | 字段 | 写入位置 | 作用 |
| --- | --- | --- | --- |
| 1 | `token` | `install.mjs`、`pition_boot stage=token`、`setupWizard` | Notion API bearer |
| 2 | `bindings` (object keyed by dbId) | 同上 | 库绑定 + 字段说明（按 dbId 索引；切空间保留所有 desc 不丢） |
| 3 | `currentBindingId` | `pition_boot stage=select_db`、`stage=describe_fields`（接管时）、`loadConfig` 兼容老格式 | 当前激活库的 dbId；运行时由 `currentBinding()` 重读 |
| 4 | `_assistantMode` | `pition_boot stage=set_mode`、`/pition-mode` | 助理模式开关（缺省 `false`）；启动时 `loadConfig` 读到 `roleState.enabled` |

**契约**：
- pi 进程不读这个文件 —— 它是 pition 自己的存储格式。
- 工厂启动时一次性读（`loadConfig`）；reload 时通过 `session_start` handler 重读；tool execute 时**必须** `loadConfig()` 重新拿当前 binding id（见 §6.1）。
- `install.mjs:60-65` 静态校验字段 type，非法 type 直接 `process.exit(1)`。
- 兼容老格式 `{ bindings: [...], currentBindingId: 0 }`（数组）：`loadConfig` 自动转 `{ bindings: { [dbId]: b }, currentBindingId: dbId }`。

## 6. 运行态陷阱（必读 — 2026-09-28 踩坑沉淀）

> **加任何新 tool / 改 tool 描述前必看本节**；不遵守 → 切库/改 token/改 description 都不会反向注入到已注册 handler。

### 6.1 启动时闭包 cfg → 切库后所有 tool 仍查旧库

**症状**：`pition_boot stage=select_db` 切到锻炼心得库，`pition_history` / `pition_query` 返回的还是 pition 库的 page。

**根因**：
```ts
// 工厂栈内 — 启动时一次性求值，所有 tool execute 闭包持有
const primary = cfg.bindings[cfg.currentBindingId];
pi.registerTool({ async execute() { const binding = primary; ... } });
```

`primary` 在工厂执行时求值一次就锁定了，之后 `cfg.currentBindingId` 改了，handler 不知道。

**修复契约**：
```ts
// 1. helper 放在 factory 外，纯 loadConfig 取最新
function currentBinding(): Binding {
  const cfg = loadConfig();
  if (!cfg) throw new Error("pition 未配置");
  const idx = cfg.currentBindingId;
  if (idx === undefined || idx === null || !cfg.bindings[idx]) {
    throw new Error("pition 没选当前库——调 pition_boot stage=select_db 选一个");
  }
  return cfg.bindings[idx];
}

// 2. 每个 tool execute 第一行
async execute(_id, params) {
  const binding = currentBinding();   // 不闭包、不缓存
  ...
}

// 3. 所有 notion(cfg, ...) → notion(null, ...)，内部 ?? loadConfig()
async function notion(cfg: PitionConfig | null, ...) {
  const real = cfg ?? loadConfig();
  ...
}
```

### 6.2 description 静态拼接 storeCtx → 切库后 agent 看到的字段说明还是旧库

**症状**：切库后 agent 仍然按旧库字段名填新库（"基础/复杂"在锻炼库可能不存在）。

**修复契约**：description 里**不**写库标题、**不**拼字段说明、**不**写死任何 cfg 衍生字符串。统一指引 agent 调 `pition_boot stage=done` 拿当前库 schema：

```ts
description: "...当前库由 pition_boot stage=select_db 选定；要看当前库字段说明先调 pition_boot stage=done。",
```

> 注：`pition_boot` 的 description **可以**动态拼装 `bootCtx`（token / 当前库 + 字段覆盖率 / 助理模式状态），因为它**本身就是**查 cfg 的工具，每次调用都重读——拼装一次没风险（不像运行态 tool 的 description 是注册时静态的）。

### 6.3 keep-alive socket 卡死 → fetch 直接 TypeError: fetch failed

**症状**：25% 丢包链路下 pi 进程内 keep-alive 连接被 RST 后，下次 fetch 抛 `TypeError: fetch failed`，无 code、无 HTTP 阶段。

**修复契约**（`fetchNotion()` `extensions/pition.ts:114`）：
- (a) **`Connection: close`**：每次新建连接，不用死掉的 keep-alive
- (b) **`AbortController.timeout(5s)`**：单次请求超时上限
- (c) **指数退避 3 次** `[500, 1500, 4500]ms`，仅重试网络层错误，不重试 HTTP 4xx/5xx
- (d) **网络层错误白名单**：`fetch failed` / `ECONNRESET` / `ETIMEDOUT` / `ENOTFOUND` / `ECONNREFUSED` / `UND_ERR_*` / `AbortError`

### 6.4 工厂前置条件检查别和助理模式共享 cfg 名

工厂里如果写：
```ts
const cfg = roleState.cfg;          // ❌ 启动闭包 + 名字撞车
pi.registerTool({ async execute() { notion(cfg, ...); } });
```

两个问题：
1. `roleState.cfg` 后续 reload 会更新（`session_start` 里赋值），但已注册的 tool handler 闭包里那个 `cfg` 不会跟着变
2. 工厂里如果重复声明 `initialCfg` 会撞车（`registerRoleMode` 上方 467 行已用了 `initialCfg`）

**正确**：用 `currentBinding()` 重读 + 工厂前置条件用临时变量名（如 `snapshotCfg`）。

### 6.5 检查清单（加新 tool 跑一遍）

- [ ] execute 第一行调 `currentBinding()`，不闭包 `primary` / `binding`
- [ ] 所有 Notion HTTP 调用走 `notion(null, ...)`，**不**用启动时 `cfg`
- [ ] description 不含 `storeCtx` / 库标题 / 字段说明；指向 `pition_boot stage=done`
- [ ] promptGuidelines 不写死"当前库是 xxx"等 cfg 衍生内容
- [ ] 工厂前置条件用临时变量名（`snapshotCfg`），不和 roleState 共享
