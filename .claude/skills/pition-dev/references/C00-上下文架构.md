# C 序列：上下文架构

pition 一切"模型能看到什么"的设计，都归结到 **9 层 system prompt sections**（按 pi 渲染顺序固定）：

```
preamble      ← 你是什么（默认：coding assistant；customPrompt 整段替换）
tools         ← 工具清单 + promptSnippet（按 selectedTools 过滤）
rules         ← 默认 guideline + toolGuidelines + promptGuidelines
docs          ← pi 文档索引（只在用户问 pi 自身时有用）
addendum      ← _appendSystemPrompt（来自 settings.json 的 appendSystemPrompt）
project_context← AGENTS.md / CLAUDE.md 等项目级上下文
skills        ← Skill 提示（按需）
cwd           ← 当前工作目录
[custom sections] ← 扩展通过 sections[key] = content 自由加（如 pition_role / pition_span）
```

源码锚点：`@earendil-works/pi-coding-agent/dist/core/system-prompt.js:64-110`。

## 关键约束

- **prompt cache**：sections 用 diffSystemPromptSections 维护 transcript 增量（`system-prompt.js:67`），只在差异时刷 cache。**整段替换 `forceSystemPrompt` 会让整段 prompt prefix miss cache**——pition 永远只用 `sections[name] = ...` 增量。
- **优先级倒挂**：preamble 在最前但**默认就是"你是 coding assistant"**——pition 几乎不该碰它（除非要彻底替换 agent 身份，不推荐）。最常用的注入点是 `rules`（promptGuidelines.push）和 `sections[name]`。
- **transcript 记录**：每次 sections 变更会作为 transcript delta 落 session——多频次注入对应多 transcript 行，影响下次 cache 复用。
