# C 序列：上下文架构

pition 一切「模型能看到什么」的设计，都归结到 **pi 的 9 层 system prompt sections**（渲染顺序固定）：

```
preamble      ← 你是什么（默认：coding assistant；customPrompt 整段替换）
tools         ← 工具清单（按 selectedTools 过滤 + promptSnippet）
rules         ← 默认 guideline + toolGuidelines + promptGuidelines
docs          ← pi 文档索引（只在用户问 pi 自身时有用）
addendum      ← settings.json 的 appendSystemPrompt
project_context← AGENTS.md / CLAUDE.md 等项目级上下文
skills        ← 已加载 skill 的发现条目（name + description + location）
cwd           ← 当前工作目录
[custom sections] ← 扩展通过 sections[key] = content 自由加（pition 用 6 个）
```

源码锚点：`@earendil-works/pi-coding-agent/dist/core/system-prompt.js`（`buildSystemPromptSections` /
`buildRules` / `diffSystemPromptSections`）。

pition 只动其中三层：**tools**（补 `promptSnippet`）、**rules**（3 条全局 + 按场景裁剪 tool guideline）、
**[custom]**（`pition_core` / `pition_scene` / `pition_fields` / `pition_runtime` / `pition_goal` / `pition_span`）。

## 关键约束

- **prompt cache**：sections 用 `diffSystemPromptSections` 维护 transcript 增量，只在差异时刷。
  **整段替换 `forceSystemPrompt` 会让整个 prompt prefix miss cache**——pition 永远只用增量。
- **优先级倒挂**：preamble 在最前但默认就是「你是 coding assistant」——pition 不动它。
  最常用的注入点是 `sections[name]` 与 rules 层的 `promptGuidelines`。
- **transcript 记录**：每次 sections 变更会作为 transcript delta 落 session——多频次注入 = 多 delta 行。
  pition 用「场景粘性」+「恒定区稳定」+「易变内容单独成段」把 delta 压到最少。
- **常驻 vs 场景 vs 按需**：判断标准见 C01 §3 决策树；有门禁兜底（C01 §5）。
- **内容不许静态化**：SOP 必须是**状态驱动的片段**（`when(state)`），别写「无论什么状态都注入的固定长文」
  ——那样必然塞进当下不成立的内容（用户反馈「提示词很容易变得静态」的根因）。
- **能力不做门禁**：可调用工具集恒为 7 个（`setActiveTools` 禁用），只有「文本足迹」随场景变。
