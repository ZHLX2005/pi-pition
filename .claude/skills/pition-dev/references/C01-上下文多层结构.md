# C01 上下文多层结构

数据快照：`extensions/pition.ts`（`pition` v0.87.1 适配）。源码：`@earendil-works/pi-coding-agent/dist/core/system-prompt.js`。

## 1. 9 层 section 详解（pi 渲染顺序固定）

| 层 | 内容 | 默认值 | pition 是否动过 | 在哪改 |
| --- | --- | --- | --- | --- |
| **preamble** | 角色定位 | `"You are an expert coding assistant operating inside pi..."` | **不动**——碰了就改 agent 身份，prompt cache 也 miss | 不动 |
| **tools** | 可用工具清单 | 按 `selectedTools` 过滤后渲染 + promptSnippet | 不动 schema / 不增删 tool | 不动 |
| **rules** | 行为准则 | 默认 2 条 + `promptGuidelines` push | **改 add 了**——`pition_role` 角色定位 + 6 条行为准则 + 属性 = 看板 段 | `buildRoleInjections` (line ~393) |
| **docs** | pi 文档索引 | 14 个 .md 链接 + 何时读 | 不动（不是 pition 关心的） | 不动 |
| **addendum** | 用户配置追加 | 来自 settings.json `appendSystemPrompt` | 不动 | 用户配置 |
| **project_context** | AGENTS.md / CLAUDE.md | 从 cwd 向上找 | 不动 | 用户配置 |
| **skills** | 加载的 skill | 按需 | 不动 | 用户配置 |
| **cwd** | 当前工作目录 | `process.cwd()` | 不动 | 不动 |
| **[custom]** | `sections[name]` | 无 | **改 add 了**——`pition_role`（角色定位）/ `pition_span`（进行中事件） | `buildRoleInjections` 内的 `sections` 对象 + before_agent_start 钩子 |

源码（`system-prompt.js:80-108`）：
```js
promptSections.preamble = customPrompt ?? "You are an expert coding assistant...";
promptSections.tools = `${tools}\n\nIn addition to the tools above...`;
promptSections.rules = buildRules(selectedTools, toolGuidelines, promptGuidelines);
promptSections.docs = `Pi documentation (read only when the user asks about pi...)`;
if (appendSystemPrompt) promptSections.addendum = appendSystemPrompt;
if (contextFiles.length > 0) promptSections.project_context = renderProjectContext(contextFiles);
if (skillFileReadTool && skills.length > 0) { ... promptSections.skills = skillsPrompt; }
promptSections.cwd = cwd;
for (const [name, content] of Object.entries(customSections)) if (content) promptSections[name] = content;
```

## 2. pition 当前所有注入点

| 注入位置 | 注入时机 | 注入内容 | 来源函数 |
| --- | --- | --- | --- |
| `promptGuidelines.push` (rules 层) | 每次 before_agent_start（助理模式开 + 有当前库） | 6 条行为准则（边界判断 / 读取决策 / 交互收尾） | `buildRoleInjections` |
| `sections.pition_role` (custom 层) | 同上 | 角色定位长文：可用工具 + 触发判断 + 反例正例 | `buildRoleInjections` |
| `sections.pition_span` (custom 层) | 每次 before_agent_start（有 active span；与助理模式无关） | 进行中 span 状态：事件名 + 持续分钟 + 最近心跳 + 操作提醒 | `renderSpanStatus` |

**关键观察**：`sections.pition_role` 和 `sections.pition_span` 是**独立注入**——`pition_span` 不受 `state.enabled` 控制（助理模式关时也注入），因为这是程序性上下文（"现在几点、用户在干嘛"），不是角色定位。

## 3. 决策树：往哪层注入？

```
我想让模型看到 X
├─ X 是「你是什么」（agent 身份） → preamble（不推荐——cache miss）
├─ X 是「行为准则 / 不要做 Y」 → rules（promptGuidelines.push）
├─ X 是「结构化主题说明」（角色 / 流程 / 工具用法） → sections[name]
│   例：pition_role、pition_span、pition_tools_usage 等
├─ X 是「可用工具列表」 → tools（不动——已自动渲染）
├─ X 是「项目特定上下文」 → project_context（写 AGENTS.md）
├─ X 是「skill 触发」 → skills（写 SKILL.md）
└─ X 是「用户全局追加」 → addendum（写 settings.json 的 appendSystemPrompt）
```

**核心规则**：
- **不要动 preamble**（除非要彻底替换 agent 身份，不推荐）
- **不要写 forceSystemPrompt**（整段替换 = cache miss）
- **优先 sections[name]**——它是 pi 设计给扩展用的最干净的注入点
- **promptGuidelines 只放 bullet 短句**——长段放 sections

## 4. cache 行为（关键）

`diffSystemPromptSections(previous, current)`（`system-prompt.js:67`）逐 turn diff：
- 相同的 section → 不刷 cache（cache prefix 复用）
- 变化的 section → 刷 transcript delta（cache 失效但只刷这一段）

**实际含义**：pition_role 注入一次后，**只要内容不变，后续每轮 model 请求都 cache hit**。同理 pition_span——但它的"持续分钟"每轮都在变（因为 now 是新 Date）→ 每轮 diff → 每轮 cache miss。

**优化**：
- `pition_span` 内容按分钟级别跳变（`< 1 分钟`内多次请求才合并）——可以接受
- `pition_role` 静态内容（不会变）——后续一直 cache hit
- 任何需要"现在几点"信息的注入都会让 cache 每轮失效——只能取舍

## 6. 反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| `forceSystemPrompt = "..."` | 整段 prompt prefix 失效，cache miss | 永远不写 |
| 往 `promptGuidelines` 写长段（>3 行） | rules section 变成大段，cache diff 多 | 拆到 `sections[name]` |
| 每轮都改 `pition_role` 内容 | cache miss | 把"会变的部分"放 `pition_span`（或独立 sections） |
| 在 preamble 里塞 pition 角色定位 | 失去 pi 默认 preamble，cache miss | 放 `sections.pition_role` |
| 把 skill 内容堆进 `pition_role` | 单 section 过大 | 每个 skill 走 `sections.<skill-name>` |

## 7. 加新注入点的流程

1. 先决定注入到哪一层（决策树）
2. 写 `buildXxx()` 函数返回 `{ guidelines, sections }` 形状
3. 在 `before_agent_start` 里 `event.systemPromptOptions.{promptGuidelines|sections}` 设置
4. 跑 smoke-load / diag-session 验证（实际注入的内容可在 TUI 看 /compact 输出对照）
5. 观察下一轮请求的 transcript delta（确认不是 cache miss 风暴）
