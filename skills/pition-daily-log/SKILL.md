# 日常记录（pition write 场景 SOP）

本场景的目标：**记全、记对位置、不打断用户**。记录是主路径，提问是补充。

## 1. 触发判断

**要记**——明确的 时间锚定（今天/刚才/3 点/昨天）+ 具体内容：

- 事实：吃了什么、花了多少、见了谁、完成什么
- **情绪/感悟也是事实**：「今天心情不错」「刚才焦虑了一下」「悟到一个道理」——用户在主动交付内容，别因为「不是事实陈述」漏掉

**不记**——闲聊、纯问答（「你觉得 x 怎么样」）、调试代码、解释概念。

用户明确说「记一下」→ 无条件记。用户没表态时你判断该记 → 回复里点一句「刚记到【库名】」让用户能否决。

## 2. 工具选择决策树

```
这条内容是「有开始+结束的时长事件」吗？（跑步/开会/午休/一轮训练）
├─ 是 → pition_span start / end（span 收尾自动写整段进 page，不是 write 两条）
│        今日目标条目的一轮 → end 带 goalItemName/goalDelta（见 pition-goal-coach skill）
└─ 否 → pition_write（日常主路径）
         ├─ 返回 warning「no_page_in_db」→ pition_create_today（逃生口，定时任务挂了）
         └─ 用户要翻旧账（上个月/上周）→ pition_history（仅显式要求）
```

- 普通记录**永远不要**拆成「开始写一条 + 结束写一条」——那是 span 的事
- 同一事件多维度（「运动 30 分钟 + 午餐 45 元」）→ **一次 write 调用**的 properties 数组里写全

## 3. 属性看板思维

能进属性的不堆正文——Notion 看板按属性统计：

- `multi_select` 加标签 / `number` 加金额时长 / `checkbox` 打卡 → 默认 append（union/累加/OR），直接传
- `title`/`select`/`status`/`url`/`email`/`phone_number` 单值字段 → 永远新值
- 要整段覆盖某字段 → 显式 `overwrite: true`
- 正文（`appendContent`）留给属性放不下的叙述：细节、感受、经过

字段名/取值不确定 → 看 boot 提供的字段说明，不猜。

## 4. 时间戳语义

- 程序自动给正文每段加 `[HH:MM]`（本地时间）——**不需要传 timestamp**
- 「我刚/刚才」= 就是现在，同样不传
- 代写历史事件（「昨天下午 3 点」）才手动传 `timestamp`（ISO 或 Unix ms）

## 5. 写入后动作

1. 简短复述「已记到【库名】」（+ page URL，如果返回里有）
2. 按 `todaySoFar` 给今日已记内容的**整体概览**（用户常忘了自己记过什么）
3. 追问 1 个自然延伸的细节（「运动 30 分钟是跑步还是力量？」）——先记原始再问优化，**不审问**；
   用户不想答就过
